Icon alternatives for the four that need another look

Each option is shown large and at real gutter size (16 px), with where it comes from and what it suggests.

Renamed

text-cursor-input Lucide
A text field with a cursor
what we first suggested; reads as “type here” more than “renamed”
tag Lucide
A name tag
a name, shown as a label; doesn’t clash with anything else in a diff
replace Lucide
Find & replace
editors’ “replace” icon; says “swapped one thing for another”
whole-word Lucide
“ab” with a baseline
editors’ “match whole word”; reads as text, not rename
rename Codicons
VS Code’s rename icon
what VS Code itself uses; text inside brackets

Edited

square-dot Lucide
Square with a dot
GitHub and VS Code use it for “modified file” in file lists. Familiar there, but not obvious on its own
pencil Lucide
Pencil
the most widely understood “edit” symbol (Docs, Notion, GitHub’s edit button)
pencil-line Lucide
Pencil writing a line
“text was edited”; a bit busier at 16 px
square-pen Lucide
Pen over a square
pairs with the + / − squares while still saying “edit”

Extracted function

split Lucide
Split
first suggestion: one becomes two. Abstract; also reads as “branch”
square-function Lucide
ƒ in a square
says “a function” — the thing that was created
symbol-method-arrow Codicons
VS Code method cube + arrow
VS Code’s method symbol with an arrow; arrow again, but tied to “function”
scissors Lucide
Scissors
“cut out” — but scissors means “cut” (clipboard) everywhere

Inlined function

merge Lucide
Merge
first suggestion. Problem: in a code-review tool “merge” means merging branches
square-function Lucide
ƒ in a square (same as extracted)
one “function” icon for both, the label says which way
list-collapse Lucide
An indented list
meant as “folded into the surrounding code”, but it mostly reads as an outline or list
fold-vertical Lucide
Fold
opposite of unfold — but editors use it for code folding (Pierre shows fold controls too)
