What you are doing

A diff tool tells reviewers things like "function X was pulled out of function Y". Each item shows one such claim from a real commit in an open-source project. Some are right, some are wrong; you are not told which, or who made the claim. Your answers are compared, after you finish, with labels written by AI checkers, to see how far those labels can be trusted.

How to judge

  • Pulled out (extract): right when code that used to sit inside Y now lives in the new function X, and Y calls X instead. Renamed variables, new parameters or small edits on the way are fine.
  • Folded back in (inline): right when the removed function X's code now sits inside Y, in place of the call.
  • Wrong when X is new code that Y never had, when Y's old code was deleted or rewritten rather than moved, or when X simply came from somewhere else.
  • Can't tell is a fine answer. Don't agonise: your first honest read is what we want.

Two made-up examples

applyDiscount pulled out of checkout Right

Before, checkout had if (user.vip) total *= 0.9. Now that line is gone, checkout calls applyDiscount(total, user), and applyDiscount holds the same logic.

formatDate pulled out of render Wrong

render used to print the raw timestamp. Now it calls a new formatDate that builds a nice string. That is new behaviour, not code that moved.
